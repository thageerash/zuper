# Project rules

- After every user prompt, append a new row to the "Prompt log" in `Process Log.dc.html`: next number, phase, the prompt with spelling corrected (wording kept), intent, one-line AI output, type (STEERED / OVERRULED / DISCARDED / KEPT), "My judgment" (only what the user actually said; otherwise "—"), result/artifact link. Update the entry count, the project checklist, and "Decisions so far" when a decision is made. Never invent entries.
- All pages share one visual style: Instrument Sans + IBM Plex Mono, background #F5F3EE, ink #1B1A17, risk #A23B1E / #F3E3DC, opportunity #2F6B4F / #E2EDE6.
- Work as a principal-level product designer on every prompt. Before replying: render and screenshot the result and look at it; audit each screen for number of actions (one primary per screen; secondary actions visibly ranked below; rare or risky actions never next to the primary), hierarchy, duplicate messages, affordances (what is tappable looks tappable, consistently), color meaning (red only for real risk), glove/outdoor hit targets, and data consistency (counts must add up across screens). Report what was checked and fixed. Audit pasted flows against the Problem Statement.
